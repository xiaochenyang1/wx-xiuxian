# 第五段位（仙阶）设计

- 日期:2026-09-02
- 状态:待评审
- 相关:`docs/superpowers/specs/2026-08-25-equipment-band-progression-design.md`(四段的形状与边界为什么对齐境界)、`docs/superpowers/specs/2026-08-31-technique-band-progression-design.md`(§3.2 品质阶梯的上界)、`docs/superpowers/specs/2026-09-01-treasure-hunt-band-progression-design.md`(寻宝按段位结算的判据)、`docs/superpowers/specs/2026-08-26-expedition-band-extension-design.md`

## 1 背景

天阶覆盖 `Lv.301..1000`，共 700 级，是前三段之和（300 级）的 2.33 倍。玩家在 Lv.301 拿到天阶身份之后，剩下 700 级里段位这条轴完全冻结：掉落品质权重、词条区间、炼丹炼器的灵石倍率、材料与强化石的产出倍率、寻宝的六行数量，全部停在天阶那一列不再变化。

这一段占裸装终身时长的绝大部分，却只有一个段位标签。补第五段修的是这件事。

## 2 为什么这次不动战力标尺

`shared/src/config/assets.ts:700` 那段注释是本设计的地基：

> A band never changes what a piece is worth in power: every slot's four configs share one `basePower`.

段位承载的是身份、品质概率与词条宽度，战力只来自品质与强化。满配那一端是"四本优秀功法升满星 + 六件法宝满强化"，它由品质阶梯与强化上限决定，**与段位有几段无关**。于是这份设计不碰下面任何一样：

- `LOADOUT_POWER_SCALE_BP = 45_000` 与 `FULL_LOADOUT_BP = 71774`
- 试炼塔 90 行门槛表的可达性（`test/progression-task-chain.test.ts` 按满配逐条重推）
- 历练门槛与修行任务链里等级与塔层的交替顺序
- 存档迁移：段位由 `equipmentBandForLevel(level)` 现算，不是存档字段，没有版本号要动

这与"再开一档品质"是两件完全不同的事。`shared/src/config/drops.ts:221` 写明第三档功法品质"would have to buy its multiplier from the tower's floor-90 threshold"——那笔账这份设计不付，因为它不开新品质档。

## 3 编译期影响是可枚举的

把 `EquipmentBand` 从 `1 | 2 | 3 | 4` 改成 `1 | 2 | 3 | 4 | 5`，`pnpm typecheck` 报 **14 处错误、12 张表，全部落在 `shared/src/config/` 下的五个文件**：`assets.ts` 2、`drops.ts` 3、`crafting.ts` 2、`treasure.ts` 6、`alchemy.ts` 1。`shared/src/domain/` 一处都没有——这是 §2 那条结论在编译器上的回声：战力、结算、装备加成没有一张按段位取值的表。

（这 14 处是第一道 tsc program 的全部产出。四道 program 是 `&&` 串起来的，补完第一道才能看到客户端与 `test/` 那两道还有没有，但 `shared` 这道覆盖了全部 `shared/src`。）

唯一不会被编译器提醒的是 `EQUIPMENT_CONFIGS` 与 `TECHNIQUE_CONFIGS`：它们是数组而不是 `Record`，少 5 件法宝或少 8 本功法要到 `equipmentConfigForSlotAndBand` 抛 `RangeError` 才发现。这一处得靠人记，或者补一条按 `(槽, 段位)` 全遍历的测试。

## 4 边界划在 Lv.601

现有边界全部对齐境界起点：凡阶止于 60（元婴期 61 之前）、灵阶止于 150（炼虚期 151 之前）、玄阶止于 300（大乘期 301 之前）。所以候选只有境界起点这几个：401（渡劫期）、501（真仙期）、601（金仙期）。

推荐 **601**，天阶收缩到 `301..600`（300 级），仙阶接 `601..1000`（400 级）：

- 段宽序列变成 60 / 90 / 150 / 300 / 400，前四段近似翻倍，最后一段收一点，与"后期把节奏交还给修为时间"这条既有判断一致。
- 401 会让天阶只剩 100 级，比玄阶还短；501 落在真仙期，而真仙期那一段刚刚被境界拆分改过（`2026-08-26-true-immortal-realm-split-design.md`），再叠一条段位边界会让同一处出现两套解释。
- 601 是"真仙 → 金仙"的语义跨越，段位名从天阶到**仙阶**正好落在这里。

已有存档不需要迁移，但要说清对 `Lv.601+` 老玩家的实际影响：**战力一点不变**（手上的天阶法宝 `basePower` 与品质、强化都没动），变的是从这一刻起新掉落的身份、词条上限、造价倍率与产出倍率——也就是他们本来已经冻结的那条轴重新开始动。

## 6 历练扩关是前置，不是可选项

寻宝三行的数量不是自己定的，判据是"该段最好的扫荡行的 50%"（`2026-09-01-treasure-hunt-band-progression-design.md`）。这条判据让"寻宝严格弱于扫荡"成为可断言的不变式，而材料曲线、强化石曲线与洞府造价三张表的上限一列都建立在它上面。

仙阶要有这个判据，就得先有仙阶的扫荡关卡。所以顺序是固定的：

1. 历练按 `2026-08-26-expedition-band-extension-design.md` 的形状扩出仙阶关卡
2. 从新关卡的扫荡产出解出寻宝三行的仙阶数量
3. 其余九张表按 §5 直接填

历练那一步没做完，寻宝三行填什么都是猜的——填错的后果不是数值偏一点，而是让上面那三张表的上限一列失去依据。

## 7 非目标

- **不开第三档功法品质，也不开第六档法宝品质。** 那会挪走满配端点，连带塔门槛表的可达性、历练门槛与任务链顺序——`shared/src/config/cave.ts:103` 拒绝给炼器室加 6,000 bp 就是为了不触发同一串连锁。
- **不动战力标尺、塔门槛、任务链。** §2。
- **不加存档迁移。** 段位现算，不落盘。
- **不动掉落频率。** 段位决定掉出什么，不决定多久掉一次；这是四段沿用至今的分工。
- **不新增面板与入口。** 仙阶复用天阶今天的每一处展示。

## 8 工作量

| 步骤 | 内容 |
| --- | --- |
| 历练扩关 | 独立一份设计，是 §6 的前置 |
| 配置 | 12 张表各补一列；`EQUIPMENT_BAND_CONFIGS` 加一行；5 件法宝、8 本功法配置 |
| 边界 | 天阶 `maxLevel` 由 1000 改 600 |
| 测试 | 按 `(槽, 段位)` 全遍历补两条，防住数组那两处编译器看不见的缺口；四段现有的种子化测试全部必须逐字节不变 |
| 文档 | 规格 §2.4 / §2.6 / §2.10 的四段表格各加一行 |

凡阶到天阶的每一个数都不动，所以所有种子化测试与现有存档的手感都是逐字节不变的——这一点和前面四份段位化设计一样，是可断言的，不是承诺。
