# 我的修仙日记

《我的修仙日记》是一款使用 Cocos Creator 3.8.8 开发的竖屏修仙放置小游戏，发布目标为浏览器预览和微信小游戏。

当前版本是纯前端单机版：仓库不包含服务端、数据库、Redis、Docker 或网络 API。角色、修为、背包、装备和设置都保存在当前浏览器或微信小游戏的本地存储中。

## 当前能力

- 自动修炼、逐秒修为投影、自动升级、境界瓶颈和突破丹突破
- 最多 24 小时离线收益，按 70% 效率结算经验、灵石和挂机掉落
- 材料、消耗品、100 格收获箱、批量收取、普通/优秀批量分解、自动分解设置和行囊扩容
- 挂机材料掉落按段位放大 ×1／×3／×6／×10，炼器页标题显示当段倍率
- 四类功法槽与六类法宝槽的装备、替换、卸下和战力重算
- 配装战力按百分比计入总战力，占比不随等级衰减，满配恒定 +717.74%
- 功法消耗同名副本升至 10 星，法宝消耗灵石与强化石必定强化至 +20
- 法宝分凡阶／灵阶／玄阶／天阶四段，按等级推导；段位决定获取品质、炼器灵石价与词条区间，不改变战力
- 法宝词条在生成时按品质与段位区间随机，法宝页展示段位、词条评分与逐条数值，收获箱候选行附段位与评分
- 洗练重掷词条并只保留更优结果，升华消耗 2 件同款法宝把传说提升至神话、神话提升至洪荒
- 行囊法宝支持锁定保护与分解，返还品质基础资源及 50% 强化投入，稀有及以上默认锁定
- 功法残页可替代缺少的同名功法副本，每本副本折算 5 张残页
- 42 级修行任务链覆盖 Lv.3 到 Lv.1000 与试炼塔第 1 到第 90 层，等级与塔层按可达成等级交替排列，Lv.8 自动发放首枚突破丹
- 主角形象二选一、一次免费改名及后续改名卡消费
- 洞府 Lv.11、试炼塔 Lv.15、伴侣 Lv.20 分段解锁，伴侣开放时显示一次性解锁提示；解锁位随存档保留，门槛提高也不会收回已开放的入口
- 洞府五座建筑可建造升级至 Lv.10，消耗灵石与挂机掉落材料，加成计入修为、灵石、掉落和战力
- 炼丹房支持四类配方，消耗材料与灵石炼制小经验丹、大经验丹、双修丹和突破丹；经验丹可单颗或批量使用
- 炼器室支持五类法宝定向打造，产出按打造者段位解析，洞府等级与段位共同改善品质概率，灵石价按段位放大而材料四段相同
- 炼丹与炼器均可单次或批量执行，批量份数受灵石、材料、行囊空位和单次 100 份上限共同约束
- 三位道侣可选其一，二次确认后结缘；消耗双修丹提升至 Lv.10，道侣加成进入统一挂机结算
- 三个本地宗门可选其一，二次确认后加入；通过物资捐献提升至 Lv.10 并获得持续加成
- 十二关顺序历练分四段铺开，以当前总战力挑战并领取一次性首通奖励；首通后可消耗寻宝令扫荡并累计各关次数
- 后六关扫荡按炼器实际消耗的比例发放材料，量级锚定该段的挂机小时数，面板按已通关数滑动显示 6 关
- 90 层试炼塔逐层攀登，门槛按 3000 战力起每层 ×1.18 递增，只能挑战已通层数的下一层且不提供扫荡；每层发放灵石、强化石与功法残页，每 5 层追加寻宝令
- 寻宝令可在历练和挂机中获得，并在历练页进行可重复的本地寻宝
- 五类本地试炼排行，使用玩家真实存档与固定 NPC 标杆排序，不伪装在线榜单
- 升级、突破、战力变化表现，以及微信安全区和竖屏适配
- 浏览器 `localStorage` 与微信 `wx.*StorageSync` 双端本地存档
- 档案页支持剪贴板备份、严格校验导入和一次性导入前回退
- 30 秒自动存档、切后台立即存档、回到前台立即离线结算
- 本地存档损坏时拒绝载入并创建新档，不把不可信数据送入 UI
- 开发构建中的离线时长模拟、固定掉落种子和资源注入面板

当前没有账号、云存档、自动跨设备同步、在线排行榜、服务端防作弊、支付或运营后台。未提前复制备份码时，清理浏览器数据、删除微信小游戏或更换设备仍会丢失本地进度。

## 工程结构

```text
assets/       Cocos 场景、UI、平台适配和本地游戏服务
shared/       会打包进客户端的数值配置与领域纯函数
docs/         游戏设计和纯前端技术说明
scripts/      浏览器与微信小游戏构建、来源追踪和静态校验脚本
settings/     Cocos Creator 项目设置
```

## 环境要求

- Node.js `22.x`
- pnpm `11.15.0`
- Cocos Creator `3.8.8`

## 本地运行

安装依赖：

```bash
pnpm install
```

在 Cocos Creator 3.8.8 中打开仓库根目录，选择 `assets/scene.scene`，点击浏览器预览即可运行。无需启动任何 API、数据库或容器。

浏览器存档键为：

```text
cultivation-diary.local-save.v1
```

调试时可以在浏览器开发者工具的 Application/Local Storage 中查看该存档。游戏内“档案”页支持复制备份、二次确认后从剪贴板导入、恢复上次导入前进度和重置本地进度。

## 验证命令

```bash
# 检查共享数值核心、Cocos 客户端和测试的 TypeScript
pnpm typecheck

# 运行结算、存档和掉落的本地测试
pnpm test

# 只构建浏览器侧共享数值核心
pnpm build:shared

# 构建并校验浏览器候选包
pnpm build:web

# 对现有浏览器候选包执行桌面和移动竖屏验收
pnpm test:e2e

# 校验产品版本、微信候选标识和 Cocos Creator 版本
pnpm verify:release-config

# 校验纯本地客户端边界
pnpm verify:source

# 构建微信 debug/release 候选包
pnpm build:wechat

# 校验现有微信候选包的来源、配置、语法和调试裁剪
pnpm verify:wechat

# 校验已经构建的 Web 与微信候选包、浏览器 E2E 及全部代码门禁
pnpm verify:candidate

# 从源码构建并完成全部候选发布门禁
pnpm release:candidate
```

测试用 vitest 运行在纯 Node 下，不需要 Cocos Creator、浏览器或微信环境：`LocalGameService` 通过构造函数接收 `PlatformAdapter`，测试传入基于 `Map` 的假实现，时间和掉落种子也都从入参注入。覆盖范围包括结算数学、本地存档、掉落、洞府、炼丹、炼器、伴侣、宗门、本地排行、历练、试炼塔、修行任务链和资产养成的规则与展示模型；Cocos 节点绘制本身不在覆盖范围内。

CI 执行依赖安装、发布配置校验、源码边界校验、严格类型检查、测试和生产依赖审计。Cocos Creator 构建和浏览器 E2E 属于本机发布门禁；先运行 `pnpm build:candidate`，再运行 `pnpm verify:candidate`。

## 微信小游戏

普通候选包使用 Cocos 测试 AppID：

```bash
pnpm build:wechat
```

生产构建只需要真实小游戏 AppID 和已经真机验证的固定基础库版本，不再需要 API 域名：

```bash
WECHAT_GAME_APP_ID=wx_REPLACE_WITH_REAL_APP_ID \
WECHAT_BASE_LIBRARY_VERSION=REPLACE_WITH_TESTED_VERSION \
pnpm build:wechat:production

WECHAT_GAME_APP_ID=wx_REPLACE_WITH_REAL_APP_ID \
WECHAT_BASE_LIBRARY_VERSION=REPLACE_WITH_TESTED_VERSION \
pnpm verify:wechat:production
```

生产参数校验通过仍不能替代微信开发者工具、真机安全区、生命周期和存储容量验收。

## 本地存档规则

- 存档采用显式 schema 版本，当前为 `1`；配置版本自 `local-1.0.0` 逐级迁移至 `local-2.9.0`，缺失的字段由迁移补齐而不是丢档。
- 每次玩法写操作前先结算当前在线收益，再更新快照并同步落盘。
- 前台每 30 秒结算并保存一次，切后台时再执行一次检查点。
- 回到前台时按离线效率结算，单次最多计算 24 小时。
- 离线掉落、任务奖励、背包、功法、法宝、洞府、炼丹炼器产物、伴侣、宗门、历练首通、扫荡次数、试炼塔已通层数、解锁位和寻宝所得与角色快照一起保存。
- 本地存储写入失败时游戏仍可继续，但顶部会提示本次进度仅保留到退出。
- 读取到结构非法、越界或版本不兼容的存档时会建立新档，避免损坏数据导致场景崩溃。
- 手动导入前会保存一次当前进度作为回退；导入失败不会替换当前会话，成功回退后恢复槽自动清除。
- 导入备份从导入时刻重新开始挂机计时，不补发备份导出至导入期间的离线收益。

详细设计和后续重新引入后端时的边界见 [游戏设计与技术规范](docs/game-design-and-technical-spec.md)。
